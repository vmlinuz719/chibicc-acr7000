# chibicc for the ACR-7000

This is a port of chibicc to the ACR-7000, the 36-bit word-addressed
machine emulated in `../acr7000`. The compiler runs on the host and
produces assembly for the emulator project's assembler, `asm2`
(`../acr7000/not_vibe_code/asm2.c`), which turns it into a paper tape
image for the emulator. Nothing in `../acr7000` was modified.

## Building and testing

    make            # chibicc, asm2, acrrun and the C library (acr/libc.o)
    make test       # chibicc's test suite, run on the emulator core

`make` expects the emulator sources in `../acr7000` (override with
`make ACR7000=path`). It builds:

- `chibicc`: the compiler driver
- `asm2`: the ACR-7000 assembler, built from the emulator's sources
- `acrrun`: a headless runner for tapes, made from the emulator's
  unmodified `cpu.c`/`fpu.c` with a batch driver in place of the
  interactive monitor (see `acr/acrrun.c`)
- `acr/libc.o`: the C library, compiled by chibicc

## Usage

    ./chibicc -o hello.ppt hello.c    # compile and link a paper tape
    ./acrrun hello.ppt                 # run it; exit status = halt code
    ./chibicc -S hello.c               # ACR-7000 assembly (hello.s)
    ./chibicc -c foo.c                 # "object file" (assembly text)
    ./chibicc -o prog.ppt foo.o bar.c  # link several units

Options specific to this port:

- `-save-temps`: keep the linked assembly as `<output>.s`
- `-nostdlib`: do not link the C library. The program then needs only
  `main`: its result becomes the halt code, and a CPU exception halts
  with 128 + the exception number. If the program defines `exit` or
  `__acr_trap(int code, int pc)`, the startup module calls them instead.
  The freestanding headers (`stddef.h`, `stdarg.h`, `stdbool.h`,
  `limits.h`, `stdint.h`, ...) need no library.
- `-mstack-top=<n>`: initial stack pointer (default 262144, the top of
  the emulator's 256K words of memory)
- `CHIBICC_ACR_STATS=1` in the environment: report how much of asm2's
  label table, forward-reference table and work area a link uses

Floating point and dynamic linking are rejected with an error: any
attempt to generate floating-point code ("floating-point is not
supported on the ACR-7000"), and `-fPIC`, `-shared`, `.so` and `.a`
inputs, `-l<lib>`, `-Wl,`/`-Xlinker`. Floating-point *types* and
constant expressions are still accepted where no code is needed
(`sizeof(double)`, `(int)2.5`, `_Generic`).

### Running on the emulator

`acrrun` loads the tape straight into memory and starts it at 02000;
characters written to the line printer go to stdout and the paper tape
reader reads stdin. With the real emulator and its monitor (numbers in
octal):

    /12                 select the paper tape reader (device 012)
    M hello.ppt         mount the tape
    /1000               the relocatable loader is preloaded at 01000
    GS                  run it; wait for "PPT: 0012 End of tape"
    P                   stop the loader (it waits for more tape)
    /2000               the program starts at 02000
    GW                  run until it halts

Output appears on the line printer (stdout); the halt code is the
value passed to `exit` or returned from `main`.

## Data model

| Type | Bits | `sizeof` | Alignment |
| --- | --- | --- | --- |
| `char`, `signed char`, `unsigned char`, `_Bool` | 9 | 1 | 1 |
| `short` | 18 | 2 | 2 |
| `int`, `long`, `long long`, enums | 36 | 4 | 4 |
| pointers | 36 | 4 | 4 |
| structs and unions | | multiple of 4 | 4 |

`CHAR_BIT` is 9 and sizes are counted in chars, so a word holds four
chars or two shorts, packed big-endian (char 0 is bits 27-35, short 0
bits 18-35, matching the order of the hardware byte instructions).
Plain `char` is signed (-256 to 255).

Pointers come in three representations, chosen by the alignment of the
type pointed to, in the manner of the Data General Nova:

| Pointer to | Value |
| --- | --- |
| word-aligned types (int, long, pointers, structs, unions, functions) | word address |
| `short` | word address << 1, plus 0 or 1 for the half |
| `char`, `void` | word address << 2, plus 0-3 for the quarter |

Pointer arithmetic counts in these units, conversions between pointer
types shift between them (`(char *)p` of an `int *p` is `p << 2`;
converting back drops the quarter), and converting a pointer to an
integer gives its representation. `void *` can hold any object pointer.
Structs are always word-aligned and padded to whole words so that
pointers to them, even incomplete ones, are word addresses.

Arrays, strings and struct members are packed; a string takes one word
per four characters (unlike the 7-bit `ds`/`dsn` strings of hand-written
assembly, five to a word). Every variable starts on a word boundary,
and a `char` or `short` variable on its own (including a parameter)
takes the low end of a word of its own.

Consequences worth knowing:

- `long` has the same rank and width as `int`, so `long` op `unsigned`
  converts to `unsigned long`. `long long` is only 36 bits.
- `<stdint.h>` has no exact-width types (`int8_t`, `uint32_t`, ...);
  the `least` types are 9, 18 and 36 bits.
- Integer constants that do not fit in 36 bits are truncated with a
  warning, as GCC does for constants too large for any type.
- `__attribute__((packed))` is ignored with a warning (a word cannot be
  accessed at a char offset), as is `_Alignas` beyond a word for
  variables. Bit-fields are allocated from the most significant end of
  their storage unit.
- Escape sequences in narrow string literals are limited to 0xff
  (character constants and wide strings can hold larger values).

## Code generation

The backend (`codegen.c`) is chibicc's stack machine retargeted, with a
few ACR-7000 specific optimizations: constant folding, direct memory
operands (including `@` indirection for `*p` and `p->first`), memory
forms of `add`/`sub`/`and`/`or`/`xor`/`mul`/`div`, branches on skip
conditions instead of materialized booleans, immediates, shifts by
constants, and sign-bit tests.

Chars and shorts are read and written with the hardware byte
instructions `ldb`/`stb`, whose pointers hold a word address and the
field's shift (bits 27-35). Through a char or short pointer that takes
three instructions to build the hardware pointer (a table lookup on the
quarter or half, `$$bp`/`$$hp`) plus the access. Chars and shorts at a
fixed place (in the frame or a global, or at a constant offset from a
word pointer variable, e.g. `p->c`) are loaded with an `ld` and one or
two rotate-and-mask instructions, and stored with `stb` through a
pointer built from the address field.

Notable idioms:

- comparisons set the carry with a no-load subtract (`subrsn`/`subrzn`)
  and branch with `.cn`/`.cz`; signed comparisons first flip the sign
  bits (`xor x, $$sgn`)
- variable shifts execute a shift template with the count ORed in
  (`edit x1, $$shl`), since shift counts are immediates
- `x * c` for powers of two becomes a shift; `mul`/`div` use MQ, AC
  and XY as the hardware requires
- constants are loaded with `ldea` (18 bits), `ldeas`+`addea`, or an
  inline literal

### Registers and calling convention

| Register | Use |
| --- | --- |
| X0 | expression result |
| X1-X5 | scratch |
| AC, MQ, XY | multiply/divide; AC holds return values |
| AP | frame pointer |
| SP | stack pointer (grows downward) |
| R14, R15 | not used (clobbered by local traps) |

Arguments are pushed right to left and the caller pops them. Each
function's label is its `save ap` mask word, so `calls f` saves AP,
pushes the mask and return address, and `rets` undoes it. In a callee:

    3+n(ap)   argument n (the first argument is at 3(ap))
    2(ap)     caller's AP
    1(ap)     save mask
    0(ap)     return address        <- AP
    -1(ap)    locals ...

Every argument takes a whole number of words; chars and shorts are
passed as words (sign- or zero-extended, as registers hold them).
Structs and unions are passed by value on the stack. A function
returning a struct or union receives a pointer to the caller's buffer
as a hidden first argument and returns that pointer in AC. Variadic
arguments simply follow the named ones, so `va_list` is a `char *`
stepping over whole words.

Only AP is preserved across calls. A C function can be called from
assembly with

            push        x0          ; last argument first
            calls       fn
            addea       sp, 1       ; pop the arguments
                                    ; result in AC

and `asm("...")` statements are copied into the output verbatim.

## Linking

asm2 assembles a single file and has no object format, so object files
are assembly text and the driver links by concatenating units after a
generated startup module (`acrlink.c`). Lines beginning with `;@`
(comments as far as asm2 is concerned) carry the symbol information
the linker needs: definitions, references, common symbols, zero-fill
regions and address constants. With this the linker reports undefined
and multiply defined symbols, places common symbols, and keeps only
the C library functions a program uses.

asm2 keeps only 10 characters of a label and gives a leading `_`, `.`,
digit and some other characters special meaning, so C names are mapped
to labels:

- external names that are already valid labels of up to 10 characters
  are kept, others become `<prefix>$<hash>` (e.g. `__heap_start`
  becomes `heap$f3gdq`)
- static names become `<prefix>?<unit><n>`
- compiler-generated labels are `$<unit><n>`; runtime labels `$$...`

where `<unit>` is a three-character id derived from the source file.

Memory layout:

    0        exception vector
    02000    crt0, used C library sections, the program in link order
    ...      large (>= 1024 words) zero-filled objects
    ...      heap (malloc), from __heap_start upward
    262143   stack, downward from -mstack-top

The startup module applies address fixups (asm2 has no address
arithmetic, so initializers like `&a[3]`, and char and short pointers,
which need a shift, are patched at startup),
clears zero-filled data, calls `main(0, argv)` and passes its result to
`exit`, which halts the CPU with that value as the halt code. CPU
exceptions are reported by `__acr_trap`, which prints the exception
and the PC and halts with code 128 + the exception number.

The linker checks asm2's limits before running it, since asm2 does not:
at most 4096 labels, 4096 unresolved forward references at a time, a
32768-word work area, and 18-bit absolute addresses (labels used in
instructions must lie below word 0400000). Large zero-filled objects
are placed after everything else and reached through 36-bit address
words, so they may extend to the end of memory.

## C library

`acr/libc.c` with headers in `acr/include` (the host's headers are not
used): `stdio.h` (printf family without floating point, puts, putchar,
getchar, fgets, ...), `stdlib.h` (malloc/free/realloc/calloc, exit,
atexit, abort, strtol family, qsort, bsearch, rand, ...), `string.h`,
`ctype.h`, `setjmp.h`, `assert.h`, `errno.h`, `limits.h` and
`stdint.h`. stdout and stderr go to the line printer (device 013) and
stdin reads the paper tape reader (device 012). The line printer only
prints complete lines, so `exit` ends a partial last line with a
newline.

## Tests

`acr/test/run.sh` runs chibicc's `test/*.c` on the emulator core (all
40 except `float.c`). Where a test depends on 8-bit little-endian chars, 32/64-bit
integers, x86-64 details or floating point, an adapted copy in
`acr/test` is used instead; `acr/test/adapt.py` generates those copies
from `test/*.c` and lists each changed expectation. `acr/test/acr7000.c`
covers the port's own code paths, and `acr/test/driver.sh` is the
driver test adapted to the ACR-7000 toolchain.
